# my-pegboard 디자인 명세

작성일: 2026-07-29
토큰 구현: `src/styles/theme.css`

이 문서는 **"화면이 어떻게 보여야 하나"**를 정한다.
왜 이렇게 정했나는 `docs/DECISIONS.md`, 무엇을 지켜야 하나는 `CLAUDE.md`에 있다.

색상값·간격값을 이 문서에 적지 않는다. 전부 토큰 이름으로 부른다.
숫자가 필요하면 `theme.css`를 본다. 두 군데 적으면 반드시 어긋난다.

## 1. 이 앱의 시각 원칙

### 원칙 0 — 계기판이지 웹페이지가 아니다

자동차 계기판은 예쁘려고 만들지 않는다. **흘끗 봤을 때 필요한 것만 읽히도록** 만든다.
이 앱도 그렇다. 사용자는 하루에 수십 번 흘끗 본다. 매번 "감상"하지 않는다.

여기서 나머지 원칙이 전부 파생된다.

### 원칙 1 — 색은 상태를 말할 때만 쓴다

**규칙:** 바탕·위젯·텍스트는 전부 무채색이다. 채도가 있는 색이 화면에 보이면
그것은 반드시 **상태**를 뜻한다. 장식으로 쓰인 색은 하나도 없다.

이유: 무채색 바탕에서 유일하게 색을 가진 것이 곧 "지금 봐야 할 것"이 된다.
위젯 헤더에 브랜드 색을 칠하면 이 신호가 죽는다.

**금지:** 그라디언트 텍스트, 위젯별 테마 색, 액센트 색의 장식적 사용.

### 원칙 2 — 크롬(chrome)은 얇을수록 좋다

**규칙:** 위젯 경계는 `border-default` 1px **하나뿐**이다. 그림자를 겹치지 않는다.
그림자는 **실제로 떠 있는 것**에만 쓴다 — 드래그 중인 위젯, 모달, 팝오버.

이유: 1px 테두리와 넓은 그림자를 같이 쓰면 "유령 카드"가 된다. 위젯 6개가 각자
그림자를 가지면 화면이 지저분해지고, 정작 모달이 떴을 때 위계가 안 생긴다.

**금지:** 위젯에 `shadow-*` 적용, 중첩 카드(위젯 안의 카드).

### 원칙 3 — 밀도는 높게, 답답하지 않게

**규칙:** 목록 행 높이는 **28px**(한 줄) / **44px**(두 줄)로 고정한다.
행 사이 여백 대신 `border-subtle` 구분선을 쓴다.

이유: 3열 위젯에 티켓이 5개만 보이면 위젯의 값어치가 없다. 여백으로 행을
구분하면 같은 높이에 항목이 절반밖에 안 들어간다. 얇은 선이 공간을 아낀다.

밀도의 한계선: **글자 크기는 줄이지 않는다.** 11px 아래로 내려가지 않는다.
빽빽하게 만드는 것은 여백을 깎아서 하는 것이지 글자를 줄여서 하는 게 아니다.

### 원칙 4 — 움직임은 상태 변화에만

**규칙:** 트랜지션은 `duration-fast`(90ms) / `duration-base`(150ms) /
`duration-slow`(220ms) 셋뿐이다. 등장 애니메이션은 없다.

이유: 이 앱이 존재하는 이유가 "Jira 웹이 느려서"다. 앱이 빠르다는 인상은
애니메이션이 아니라 **그 부재**에서 온다. 0.3초짜리 페이드인은 0.3초 느린 것이다.

**절대 금지:** 드래그 중인 위젯에 `transition` 적용. 60fps 목표가 즉시 깨진다.

### 원칙 5 — 실패는 반드시 보인다

**규칙:** 모든 위젯은 아래 7개 상태 중 정확히 하나에 있고, 그 상태가 **헤더만 봐도**
구분된다. (3장 참조)

이유: 사용자는 코드를 안 본다(CLAUDE.md 대전제 2). 콘솔 로그는 없는 것과 같다.

## 2. 위젯 해부 — WidgetShell

모든 위젯이 공유하는 껍데기. 위젯 구현체는 **본문만** 그린다.
헤더·상태·에러·푸터는 셸이 전부 처리한다.

### 2.1 배치도

```
┌──────────────────────────────────────────────────────────┐
│▓▓▓▓▓▓▓▓▓▓▓▓▓  refresh-bar (2px, 갱신 중에만)  ▓▓▓▓▓▓▓▓▓▓▓│
├──────────────────────────────────────────────────────────┤
│  내 티켓                          ⟳   ⚙   ✕              │ ← 헤더 32px
│  ↑제목 base/600                   ↑액션(hover 시 등장)     │
├──────────────────────────────────────────────────────────┤ ← border-subtle
│                                                          │
│  ABC-412   로그인 시 토큰 갱신 실패      [진행중]  김현우 │ ← 행 28px
│  ─────────────────────────────────────────────────────   │ ← border-subtle
│  ABC-408   대시보드 초기 로딩 최적화     [할일]    김현우 │
│  ─────────────────────────────────────────────────────   │
│  XYZ-77    강의 목록 페이지네이션        [완료]    김현우 │
│                                                          │ 본문
│                        (스크롤)                          │ (flex-1)
│                                                          │
├──────────────────────────────────────────────────────────┤ ← border-subtle
│  3분 전 갱신                                       30건  │ ← 푸터 24px
│  ↑xs/tertiary                              ↑xs/tertiary  │
└──────────────────────────────────────────────────────────┘
   ↑ border-default 1px, radius-lg, bg surface-raised
```

### 2.2 헤더 — 32px 고정

| 요소 | 사양 |
|---|---|
| 높이 | 32px 고정 (`space-widget-pad-y` 상하 + 내용 높이) |
| 좌우 여백 | `space-widget-pad-x` (12px) |
| 제목 | `text-base`(14px) / `font-weight-semibold` / `text-primary` |
| 제목 넘침 | 한 줄 고정, `text-overflow: ellipsis`. 줄바꿈 금지 |
| 액션 영역 | 우측 정렬, 아이콘 간 4px |
| 아이콘 크기 | 14px (lucide `size={14}`) |
| 아이콘 히트박스 | **24×24px** — 시각 크기보다 크게. 드래그 중 오클릭 방지 |
| 배경 | 없음. 본문과 같은 `surface-raised` |
| 하단 | `border-subtle` 1px |

**액션 버튼 4종과 표시 규칙:**

| 버튼 | 아이콘 | 항상 보임? | 색 |
|---|---|---|---|
| 새로고침 | `RefreshCw` | **항상** | `text-tertiary` → hover `text-secondary` |
| 설정 | `Settings2` | hover 시에만 | 동일 |
| 삭제 | `X` | hover 시에만 | hover 시 `danger` |
| 상태 표시 | (상태별) | 상태에 따라 | 3장 참조 |

**왜 새로고침만 항상 보이나:** 유일하게 자주 쓰는 버튼이다. 설정·삭제는 어쩌다
한 번이므로 평소에 자리를 차지할 이유가 없다. hover 시 나타나면 충분하다.

**왜 삭제가 hover 전용인가:** 항상 보이면 드래그하다 잘못 누른다.
삭제는 **확인 없이 즉시 실행**하되 되돌리기를 제공한다 — 확인 모달은 매번 성가시고,
되돌리기는 실수했을 때만 쓰인다. (되돌리기는 전역 배너 자리에 5초간)

**헤더는 드래그 핸들이다.** 제목 영역이 `react-grid-layout`의 `.drag-handle`.
액션 버튼 영역은 `onMouseDown` 전파를 막는다. 안 막으면 버튼 클릭이 드래그로 먹힌다.

### 2.3 본문

| 항목 | 사양 |
|---|---|
| 높이 | `flex: 1`, 헤더/푸터를 뺀 나머지 전부 |
| 좌우 여백 | 없음 — 행이 위젯 폭 끝까지 간다 |
| 행 내부 여백 | `space-widget-pad-x` (12px) |
| 스크롤 | `overflow-y: auto`. 넘칠 때만 |
| 최소 높이 | 3행분 (84px). 그리드 `minH`로 강제 |

**왜 본문에 좌우 여백이 없나:** 행 hover 배경이 위젯 폭 끝까지 차야 "이 행 전체가
클릭 대상"으로 읽힌다. 여백이 있으면 hover 영역이 떠 있는 것처럼 보인다.

### 2.4 푸터 — 24px 고정

| 항목 | 사양 |
|---|---|
| 높이 | 24px |
| 글자 | `text-xs`(12px) / `text-tertiary` |
| 좌측 | 마지막 갱신 시각 — "3분 전 갱신" |
| 우측 | 항목 수 — "30건" |
| 상단 | `border-subtle` 1px |

**⚠️ "총 42건 중 30건" 형태를 만들지 말 것.** 신규 Jira 검색 엔드포인트가
total을 주지 않는다. (CLAUDE.md / DECISIONS 8장) 표시는 **"30건"**뿐이다.

**푸터를 숨기는 경우:** Todo 위젯처럼 갱신 개념이 없는 위젯. 셸이 `footer={null}`
을 받으면 푸터를 통째로 없애고 본문이 그 공간을 가진다.

### 2.5 위계 정리

한 위젯 안의 시각 위계는 **네 단계**뿐이다. 더 쪼개면 흐려진다.

1. **본문 1차** — 티켓 요약문. `text-sm` / `text-primary`
2. **본문 2차** — 티켓 키, 상태 배지. `text-xs` / 의미색 또는 `text-secondary`
3. **껍데기** — 위젯 제목. `text-base` / `semibold` / `text-primary`
4. **메타** — 시각, 개수, 담당자. `text-xs` / `text-tertiary`

**주의:** 위젯 제목(3)이 본문(1)보다 크지만 **더 눈에 띄면 안 된다**.
제목은 위치(맨 위)로 이미 구분된다. 색까지 강조하면 내용보다 껍데기가 먼저 읽힌다.

## 3. 위젯 상태 — 7종

**이 장이 이 문서에서 가장 중요하다.** 사용자가 코드를 안 보므로 상태는
화면에서 구분돼야 한다.

### 3.1 요약표

| 상태 | 본문 | 헤더 신호 | 푸터 | 사용자가 읽어야 할 것 |
|---|---|---|---|---|
| `idle` | 비어 있음 | 없음 | "아직 불러오지 않음" | 곧 뜬다 |
| `loading` | **스켈레톤** (최초만) | refresh-bar | "불러오는 중" | 처음이라 기다린다 |
| `ready` | 목록 | 없음 | "N분 전 갱신 · N건" | 정상 |
| `stale` | **목록 유지** + 감쇠 | 상단 앰버 실선 | "N분 전 데이터 · 재시도 중" | 오래됐지만 맞다 |
| `error-transient` | **목록 유지** + 감쇠 | 상단 앰버 실선 | 하단 경고줄 | 실패했지만 데이터는 있다 |
| `error-permanent` | **에러 블록으로 교체** | 없음 | 숨김 | 내가 뭔가 해야 한다 |
| `empty` | 빈 상태 안내 | 없음 | "0건" | 쿼리는 맞고 결과가 없다 |

### 3.2 각 상태의 생김새

#### `idle` — 아직 요청 전

앱 시작 직후 캐시도 없는 위젯. **거의 보이지 않는 상태**여야 한다.

```
┌────────────────────────────┐
│  내 티켓              ⟳    │
├────────────────────────────┤
│                            │
│                            │  ← 완전히 빈 본문. 스피너 없음
│                            │
├────────────────────────────┤
│  아직 불러오지 않음         │  ← xs / text-quaternary
└────────────────────────────┘
```

**스피너를 안 두는 이유:** idle은 보통 100ms 안에 loading으로 넘어간다.
스피너를 그리면 깜빡임만 만든다.

#### `loading` — 최초 로딩 (캐시 없음)

**이 상태는 앱 최초 실행 때만 나온다.** 캐시가 있으면 절대 여기 오지 않는다.

```
┌────────────────────────────┐
│▓▓▓▓▓▓▓▓ refresh-bar ▓▓▓▓▓▓│
├────────────────────────────┤
│  내 티켓              ⟳    │
├────────────────────────────┤
│  ▬▬▬▬  ▬▬▬▬▬▬▬▬▬▬▬  ▬▬▬  │  ← 스켈레톤 3행
│  ▬▬▬▬  ▬▬▬▬▬▬▬▬▬    ▬▬▬  │     surface-hover 색
│  ▬▬▬▬  ▬▬▬▬▬▬▬▬▬▬▬▬ ▬▬▬  │     펄스 애니메이션 없음
├────────────────────────────┤
│  불러오는 중                │
└────────────────────────────┘
```

**스켈레톤에 펄스를 안 넣는 이유:** 위젯 6개가 동시에 깜빡이면 화면이 요동친다.
정적인 회색 막대로 충분히 "로딩 중"으로 읽힌다.

#### `loading` — 갱신 (캐시 있음) ★핵심

**이 경우 본문을 절대 건드리지 않는다.**

```
┌────────────────────────────┐
│▓▓▓▓▓▓▓▓ refresh-bar ▓▓▓▓▓▓│  ← 유일한 변화. 2px 진행선
├────────────────────────────┤
│  내 티켓              ⟳    │  ← 아이콘 회전 (선택)
├────────────────────────────┤
│  ABC-412  로그인 토큰...   │  ← 기존 데이터 그대로.
│  ABC-408  대시보드 초기... │     흐려지지도, 사라지지도 않는다
│  XYZ-77   강의 목록...     │
├────────────────────────────┤
│  3분 전 갱신          30건 │  ← 그대로. 성공 후에 바뀐다
└────────────────────────────┘
```

> **이것이 이 앱의 핵심 약속이다.**
> 갱신 중에 목록이 사라지거나 스켈레톤으로 바뀌면, 그 순간 이 앱은
> Jira 웹과 같아진다. `theme.css`의 `.refresh-bar`가 이걸 위해 존재한다.

**규칙으로 못 박음:** 본문에 데이터가 한 번이라도 들어온 뒤로는,
`error-permanent`가 아닌 한 **본문이 비워지는 경우는 없다.**

#### `ready` — 정상

기준 상태. 특별한 장식이 없다. 위 배치도 그대로.

#### `stale` — 캐시 표시 중 ★이 앱 고유

갱신에 실패했지만 직전 성공 데이터가 있다. **틀린 게 아니라 오래된 것.**

```
┌────────────────────────────┐
│════════════════════════════│  ← stale-border 앰버 실선 2px
├────────────────────────────┤
│  내 티켓         ⏱   ⟳    │  ← 시계 아이콘 (stale 색)
├────────────────────────────┤
│  ABC-412  로그인 토큰...   │  ┐
│  ABC-408  대시보드 초기... │  │ opacity-stale-body (0.62)
│  XYZ-77   강의 목록...     │  ┘ 목록은 그대로. 물러나 있을 뿐
├────────────────────────────┤
│  12분 전 데이터 · 재시도 중 │  ← stale 색
└────────────────────────────┘
```

**설계 근거 세 가지:**

1. **왜 빨강이 아닌가** — 빨강은 "이 목록이 틀렸다"로 읽힌다. 실제로는 맞는
   데이터다. 12분 전 기준으로 정확하다. 앰버는 "주의해서 봐라"이지
   "잘못됐다"가 아니다.

2. **왜 색을 바꾸지 않고 opacity를 쓰나** — 텍스트 색을 회색으로 바꾸면
   상태 배지의 의미색(진행중=파랑, 완료=초록)까지 죽는다. 투명도는 전체를
   균일하게 뒤로 보내므로 색 의미가 보존된다.

3. **warning과 어떻게 구별하나** — 둘 다 앰버 계열이라 색만으로는 부족하다.
   **표현 방식으로 구분한다:**

   | | warning | stale |
   |---|---|---|
   | 배경 채움 | 있음 (`warning-muted`) | **없음** |
   | 아이콘 | 삼각형 경고 | 시계 |
   | 요구 | 행동 | 없음 (알리기만) |
   | 위치 | 본문 안 | 위젯 테두리 |

**푸터 문구는 경과 시간에 따라 바뀐다:**

| 경과 | 문구 |
|---|---|
| ~10분 | `N분 전 데이터` |
| 10분~2시간 | `N분 전 데이터 · 재시도 중` |
| 2시간~ | `N시간 전 데이터 · 연결 확인 필요` |
| 24시간~ | `어제 데이터` / `N일 전 데이터` |

시간이 지날수록 문구가 강해진다. 색은 그대로 stale이다. **색을 danger로
바꾸지 않는다** — 오래된 것은 여전히 틀린 것이 아니다.

#### `error-transient` — 일시적 실패 (재시도 중/소진)

429·네트워크·5xx. 지수 백오프 3회. **재시도 중에는 `stale`과 똑같이 보인다.**

3회 다 실패하면 하단에 얇은 경고줄이 **추가**된다:

```
┌────────────────────────────┐
│════════════════════════════│  ← stale-border 유지
├────────────────────────────┤
│  내 티켓         ⏱   ⟳    │
├────────────────────────────┤
│  ABC-412  로그인 토큰...   │  ┐ 목록 유지 + 감쇠
│  ABC-408  대시보드 초기... │  ┘
├────────────────────────────┤
│ ⚠ 연결 실패 · 5분 후 재시도  [지금] │ ← 24px, warning-muted 배경
├────────────────────────────┤
│  18분 전 데이터             │
└────────────────────────────┘
```

| 항목 | 사양 |
|---|---|
| 높이 | 24px |
| 배경 | `warning-muted` |
| 글자 | `text-xs` / `warning` |
| 우측 | `[지금]` 텍스트 버튼 — 백오프를 기다리지 않고 즉시 재시도 |

**다음 폴링이 성공하면 경고줄과 stale 표시가 함께 사라진다.** 잔여물을 남기지 않는다.

#### `error-permanent` — 영구적 실패

401·403·400. 재시도 없음. **본문을 교체하는 유일한 에러 상태.**

```
┌────────────────────────────┐
│  내 티켓              ⚙    │  ← 새로고침 버튼 숨김 (눌러도 소용없음)
├────────────────────────────┤
│                            │
│         ⚠                  │  ← 20px, danger
│    JQL 문법 오류            │  ← base / semibold / text-primary
│                            │
│  Field 'assigne' does      │  ← xs / text-secondary
│  not exist or you do not   │     Jira 원문 그대로
│  have permission to view   │     (Jira 메시지가 친절하다)
│  it.                       │
│                            │
│      [쿼리 수정]            │  ← 행동 버튼. 위젯 설정을 연다
│                            │
└────────────────────────────┘  ← 푸터 숨김
```

**3단 구성을 지킨다: 무엇이 / 왜 / 어떻게.**

| 상황 | 제목 | 본문 | 버튼 |
|---|---|---|---|
| 400 JQL 오류 | `JQL 문법 오류` | Jira 원문 메시지 | `[쿼리 수정]` |
| 403 권한 없음 | `접근 권한 없음` | 어떤 프로젝트인지 | `[쿼리 수정]` |
| 401 토큰 만료 | — | **위젯에 안 그린다** | (5장 참조) |

**왜 새로고침 버튼을 숨기나:** 눌러도 같은 에러가 난다. 남겨두면 사용자가
계속 누르며 "왜 안 되지"를 반복한다. 행동 버튼이 유일한 출구여야 한다.

**Jira 원문을 번역 안 하는 이유:** Jira의 JQL 에러 메시지는 어느 필드가 틀렸는지
정확히 알려준다. 우리가 "쿼리가 잘못되었습니다"로 바꾸면 정보가 사라진다.

#### `empty` — 결과 0건

에러가 아니다. **쿼리는 정상이고 조건에 맞는 항목이 없다.**

```
┌────────────────────────────┐
│  내 티켓              ⟳    │
├────────────────────────────┤
│                            │
│    조건에 맞는 티켓이 없음   │  ← sm / text-secondary
│                            │
│    assignee = currentUser  │  ← 2xs / mono / text-quaternary
│    AND resolution = ...    │     실제 쿼리를 보여준다
│                            │
├────────────────────────────┤
│  방금 갱신                 0건│
└────────────────────────────┘
```

**쿼리를 보여주는 이유:** 빈 결과의 원인은 대개 쿼리다. "없음"만 쓰면 사용자는
앱이 고장난 건지 진짜 없는 건지 모른다. 쿼리가 보이면 스스로 판단한다.

**"할 일이 없네요! 🎉" 류를 쓰지 않는다.** 하루 수십 번 보는 화면이다.
두 번째부터는 성가시다.

### 3.3 상태 전이

```
      ┌──────────────────────────────────────────┐
      │                                          │
   idle ──▶ loading ──┬──▶ ready ──▶ empty       │
      ▲               │       │                  │
      │               │       │ 폴링              │
      │               │       ▼                  │
      │               │   loading(갱신)           │
      │               │       │                  │
      │               │  일시적 실패 ▼            │
      │               │    stale ──▶ error-transient
      │               │       │           │      │
      │               │       └───────────┴──────┘ 성공 시 ready
      │               │
      │          영구적 실패
      │               ▼
      └────── error-permanent  (설정 변경 시에만 탈출)
```

**불변 규칙:**
- `ready`를 한 번 거친 뒤에는 `loading`이 본문을 비우지 않는다
- `stale`에서 `error-permanent`로 갈 수 있다 (재시도 중 401 발생)
- `error-permanent`는 사용자 행동(설정 변경·재인증) 없이 벗어나지 않는다

## 4. Jira 목록 행

위젯 본문의 기본 단위. **3열 폭(약 240px)에서도 읽혀야 한다**는 것이 설계 제약이다.

### 4.1 한 줄 배치 (기본)

```
│ ABC-412   로그인 시 토큰 갱신 실패        [진행중]  현우 │
  └─┬───┘   └────────────┬───────────┘      └──┬──┘  └─┬┘
   64px          flex: 1 (넘치면 ellipsis)     56px    20px
   mono/xs        sm/primary                  2xs      아바타
   고정폭          우선순위 색 좌측 2px 표시
```

| 요소 | 폭 | 사양 |
|---|---|---|
| 우선순위 | 2px | 행 좌측 세로선. `priority-*` 색. P3(Medium)는 **그리지 않음** |
| 티켓 키 | 64px 고정 | `.ticket-key` (mono/xs/semibold) |
| 요약 | `flex: 1` | `text-sm` / `text-primary` / 한 줄 ellipsis |
| 상태 배지 | 내용만큼 | `text-2xs`, `status-*-muted` 배경 |
| 담당자 | 20px | 아바타 원형. 없으면 회색 원 |

**행 높이 28px 근거:** 13px 글자 × 1.45(한글 행간) = 18.85px + 상하 7px = 32.85px…
는 너무 크다. 행간을 `leading-tight-latin`으로 두고 상하 4.5px씩 → **28px**.
한 줄만 표시하므로 한글 행간 규칙의 예외를 허용한다.

**우선순위를 좌측 2px 선으로 표시하는 이유:** 아이콘을 두면 24px를 먹는다.
3열 위젯에서 24px는 요약문 3~4글자다. 2px 선은 공간을 거의 안 쓰면서
스캔할 때 확실히 보인다. **P3(Medium)를 안 그리는 것이 요점** — 대부분의
티켓이 Medium이므로, 그리면 모든 행에 선이 생겨 신호가 사라진다.

> 원칙 2("얇은 크롬")와 craft-floor의 "1px 넘는 컬러 border-left 금지"가
> 충돌하는 지점이다. 여기서는 **정보 밀도가 이긴다** — 이 선은 장식이 아니라
> 5단계 데이터를 2px에 담는 수단이고, 대안(아이콘)은 폭 제약을 못 지킨다.
> 2px로 제한하고 P3를 비워 남용을 막는다.

### 4.2 두 줄 배치 (6열 이상)

폭이 넉넉하면 메타를 둘째 줄로 내리고 요약에 공간을 준다.

```
│ ABC-412   로그인 시 토큰 갱신 실패                        │
│           [진행중]  현우  ·  2시간 전                     │  44px
   └─┬───┘  └──┬──┘  └┬┘     └───┬───┘
    64px      배지   담당자    상대 시각 (xs/tertiary)
```

### 4.3 상태 배지

| 항목 | 사양 |
|---|---|
| 글자 | `text-2xs`(11px) / `font-weight-medium` |
| 여백 | 좌우 6px / 상하 1px |
| 반경 | `radius-xs` |
| 배경 | `status-{todo\|progress\|done}-muted` |
| 글자색 | `status-{todo\|progress\|done}` |

**표시 문구는 Jira 원본 상태명이다** ("코드리뷰", "QA 대기").
카테고리명("진행중")으로 바꾸지 않는다 — 사용자는 팀의 실제 워크플로우 이름으로
기억한다. **색만 카테고리를 따른다.**

**넘침 처리:** 상태명이 6글자를 넘으면 `max-width: 72px` + ellipsis.
전체 이름은 `title` 속성으로.

**배지는 누를 수 있다** (DECISIONS 11.5 개정). 누르면 상태 전이 팝오버가 열린다.
3열(점으로 축약된 상태)에서도 마찬가지다.

| 항목 | 사양 |
|---|---|
| 팝오버 배경 | `surface-overlay` + `border-subtle` 1px + `shadow-popover` |
| 반경 | `radius-lg` |
| 최소 폭 | 200px (3열 위젯보다 좁아지면 상태명이 잘려 고를 수 없다) |
| 최대 폭 | 280px |
| 전이 한 줄 | 6px 카테고리 점 + 도달 상태 이름. **배지처럼 색 배경을 깔지 않는다** |
| 로딩 | 스켈레톤 3줄. **펄스 없음** (9장) |
| 실패 | 팝오버 **안에** 인라인. 전역 배너가 아니다 (5.1) |

전이 목록에 색 배경을 안 쓰는 이유: 여섯 줄이 전부 색 블록이면 원칙 1의
"색은 상태를 말할 때만"이 무의미해진다. 점이면 카테고리는 충분히 읽힌다.

**필수 필드가 걸린 전이**는 실행 버튼이 아니라 `입력 필요` + 외부 링크 아이콘이
붙은 링크가 된다. 앱에서 못 하는 일을 **누르기 전에** 말한다.

### 4.4 담당자

| 폭 | 표시 |
|---|---|
| 3~4열 | 아바타만 (20px 원형) |
| 5열+ | 아바타 + 이름 (성 제외 2글자: "현우") |
| 미할당 | 점선 테두리 빈 원 |

**이미지 로딩 실패 시:** 이름 첫 글자 1자 + `surface-hover` 배경.
깨진 이미지 아이콘을 절대 노출하지 않는다.

### 4.5 상대 시각

| 경과 | 표시 |
|---|---|
| ~1분 | `방금` |
| ~1시간 | `N분 전` |
| ~24시간 | `N시간 전` |
| ~7일 | `N일 전` |
| 그 이상 | `M월 D일` |

**절대 시각은 `title` 속성으로.** 화면에는 상대 시각만.

### 4.6 행 상호작용

| 상태 | 표현 |
|---|---|
| hover | 배경 `surface-hover`, 90ms |
| focus | `focus-ring` outline (키보드) |
| active | 배경 `surface-active` |
| 클릭 | 상세 모달 열기 |
| ⌘+클릭 | 브라우저에서 Jira 열기 |
| 티켓 키 클릭 | 브라우저에서 Jira 열기 (모달은 안 열린다) |
| **상태 배지 클릭** | **상태 전이 팝오버** (모달은 안 열린다) |

**행 전체가 클릭 대상이다.** 티켓 키만 링크로 만들지 않는다 — 3열 위젯에서
64px 타깃은 너무 작다.

**행 안의 클릭 대상은 `stopPropagation`한다.** 안 하면 행 클릭까지 번져서
브라우저(또는 팝오버)와 상세 모달이 **동시에** 열린다. 티켓 키에서 한 번,
상태 배지에서 또 한 번 같은 함정이 있었으므로 테스트로 고정해뒀다.

### 4.7 최소 폭 검증

3열(240px) 기준 실제 배분:

```
12(좌여백) + 2(우선순위) + 64(키) + 8(간격) + ?(요약) + 8 + 56(배지) + 8 + 20(아바타) + 12(우여백)
= 190px 고정 + 요약 50px
```

요약 50px = 한글 약 3~4자. **너무 좁다.**

→ **3열에서는 상태 배지를 점(dot)으로 축약한다:**

```
│ ABC-412   로그인 시 토큰 갱신 실...  ● 현우 │
                                      ↑ 6px 원, status 색
```

배분: 190 - 56 + 6 = 140px 고정 → 요약 **100px** (한글 7~8자). 수용 가능.

| 폭 | 상태 표현 | 담당자 |
|---|---|---|
| 3열 | 6px 점 | 아바타 |
| 4열+ | 텍스트 배지 | 아바타 |
| 5열+ | 텍스트 배지 | 아바타 + 이름 |

점 표현은 색에만 의존하므로 **`title` 속성에 상태명을 반드시 넣는다.**

## 4-b. 티켓 상세 모달

폭 `max-w-3xl`. `ui/Modal`을 그대로 쓴다(포털·ESC·배경 스크롤 잠금).

### 4-b.1 배치도

```
┌────────────────────────────────────────────────────────┐
│ ‹  ABC-142   [Jira에서 열기]                       ✕   │ 고정 헤더
├────────────────────────────────────────────────────────┤
│ 위젯 드래그 시 레이아웃 저장이 중복 호출됨              │ text-lg
│ [진행 중]  [Devth] 기능  ·  Medium                     │ 배지 줄
│                                                        │
│ 담당자  🧑 김현우      보고자  🧑 박서준                │ 2열 메타 그리드
│ 생성    3일 전         수정    2시간 전                 │ title에 절대시각
│ 마감    2026-08-04     스프린트 Sprint 12               │ 없는 항목은 행째로 뺀다
│ 상위    ABC-400 로그인 개선                             │ 클릭 → 모달 전환
│ 라벨    [frontend] [bug]                               │
│ ───────────────────────────────────────────────        │
│ 설명                                                    │
│   (ADF 렌더러)                                          │
│ ───────────────────────────────────────────────        │
│ 코멘트 3                                                │
│   … 이전 39개는 Jira에서 보기    (total > 20일 때만)    │
│   🧑 박서준  3일 전                                     │
│      (ADF)                                             │
└────────────────────────────────────────────────────────┘
```

`‹`는 스택이 2개 이상일 때만 보인다.

### 4-b.2 상태별 표현

이 모달의 핵심은 **스피너로 시작하지 않는 것**이다. 목록이 이미 아는 것은 즉시 그린다.

| 상황 | 표현 |
|---|---|
| 목록에서 열었을 때 | 제목·상태·담당자·우선순위·유형·날짜·상위·스프린트가 **0ms에** 뜬다. 설명·코멘트 자리만 "불러오는 중…" |
| 보고자·라벨 | 상세가 오기 전까지 보고자는 "불러오는 중…", 라벨은 행 자체가 없다 |
| 전환으로 들어왔을 때 | 골격이 없다. 헤더에 키만 뜨고 본문은 "불러오는 중…" |
| 상세 실패 (골격 있음) | 골격을 **유지**하고 설명 자리에만 에러 + `[다시 시도]` `[Jira에서 열기]` |
| 상세 실패 (골격 없음) | 본문 전체가 에러 + 같은 버튼 2개 |
| 코멘트만 실패 | 설명은 그대로. 코멘트 자리에만 에러 + `[다시 시도]` |
| 401 | 위와 별개로 **전역 배너**가 뜬다 (5.2). 모달 안에 같은 말을 두 번 쓰지 않는다 |
| 코멘트 0건 | "코멘트가 없습니다" |
| 설명 없음 | "설명이 없습니다" (회색) |

### 4-b.3 ADF 본문

- 문단 행간은 `leading-relaxed-ko`(1.75) — 7.3의 한글 본문 값
- 표는 **반드시** `overflow-x-auto` 컨테이너 안. 넓은 표가 모달 폭을 뚫으면 본문이 통째로 밀린다
- 코드블록은 hover 시 복사 버튼. 언어가 있으면 우상단에 표기
- 미지원 노드: `[지원하지 않는 요소: X]` 회색 박스. **자식은 계속 그린다**
- 미지원 **마크**는 표시하지 않고 텍스트만 그린다 — 마크마다 배지를 붙이면 본문이 읽히지 않는다
- 이미지: 자리에 `[이미지]`, 본문 끝에 "이미지 N개 — Jira에서 보기" 한 번

### 4-b.4 티켓 참조

본문의 `PROJ-123`, 내부 `inlineCard`, 상위 항목은 **모달 안에서 전환**한다.
`‹`로 돌아온다. **ESC는 모달 전체를 닫는다** — 스택을 한 겹씩 벗기지 않는다.
한 키가 두 가지 뜻을 가지면 무엇이 일어날지 예측할 수 없다.

`code`·`link` 마크가 걸린 텍스트에서는 티켓 키를 링크로 바꾸지 않는다
(링크 안의 링크, 코드 안의 문자열).

## 4-c. 티켓 생성 모달

폭 `max-w-xl`. 진입은 타이틀바 ✚ 또는 `⌘⇧N`. Jira 연결이 없으면 버튼을 숨긴다.

```
┌─ 티켓 생성 ────────────────────────────────────┐
│ 프로젝트 [DTH ▾]  ↻ 3일 전                      │
│ 유형    [[Devth] 기능 ▾]                        │
│ 요약    [                                   ]  │ ← autoFocus
│ 설명    [                                   ]  │
│         서식·표·이미지는 생성 후 Jira에서        │
│ 우선순위 [Medium ▾]   마감 [2026-08-04]         │
│ ☑ 나에게 할당 (김현우)                          │
│                              [취소]  [생성]     │
└────────────────────────────────────────────────┘
```

| 상황 | 표현 |
|---|---|
| 두 번째 이후 열기 | 프로젝트 목록이 **0ms**에 뜬다(디스크 캐시). ↻ 옆에 "N일 전" |
| 하위작업 유형 | 드롭다운에서 빼되 **"하위 작업 유형 N개는 상위 티켓이 필요해 제외했습니다"**를 적는다 |
| createmeta 실패 | 폼은 계속 쓸 수 있다. 우선순위만 5단계 폴백 |
| 폼에 없는 필수 필드 | 노란 경고에 필드 이름을 나열 |
| 성공 | **모달을 닫지 않는다.** `✓ DTH-421 이(가) 만들어졌습니다` + [Jira에서 열기] [상세 보기] [하나 더 만들기] [닫기] |
| 실패 (일반) | Jira 원문 + [다시 시도]. **입력은 그대로 둔다** |
| 실패 (응답 없음) | ⚠️ 가장 강한 경고 + **[생성] 버튼 비활성화**. 티켓이 만들어졌을 수 있어 다시 누르면 중복이 된다 |

성공에 토스트를 쓰지 않는 이유는 5.3과 같다 — 만들어진 키는 사용자가 다음 행동을
고를 근거이지 흘려보낼 알림이 아니다.

## 4-d. Todo 위젯

폭이 좁아도 되는 유일한 위젯이다(`minLayout: 2×5`). 목록이라 세로가 길어야 쓸모 있다.

### 4-d.1 배치도

```
┌─ 할 일 ────────────────────┐
│ ◀   8월 1일 (금) (오늘)  ▶ │  날짜 헤더
│ ↻ 어제에서 3개 [되돌리기] ✕│  이월 배너 (있을 때만)
│ ─────────────────────────  │
│ ☐ ↻12일째  배포 스크립트    │  danger  (7회 이상)
│ ☐ ↻3일째   PR 리뷰         │  warning (3~6회)
│ ☐ ↻1일째   문서 정리        │  tertiary(1~2회)
│ ☐          오늘 쓴 항목     │  배지 없음
│ ─────────────────────────  │  구분선
│ ☑ 끝낸 항목                │  취소선 — 지우지 않는다
│ ─────────────────────────  │
│ ＋ 할 일 추가               │  하단 고정
└────────────────────────────┘
```

새로고침 버튼이 없다 — `pollable: false`라 WidgetShell이 숨긴다. 우리가 호출할
외부 API가 없으므로 누를 것이 없다.

대신 **↓(미완료 가져오기)** 가 설정 버튼 왼쪽에 붙는다. 자동 이월을 꺼둔
사용자를 위한 수동 경로다. **가져올 것이 있을 때만 보이고**, hover하면 무엇이
딸려오는지 목록으로 알려준다(앞 5개 + "외 N개"). 눌러도 아무 일이 없는 버튼은
사용자가 고장으로 여기고 다시 누른다.

### 4-d.2 이월 배지

숫자는 **경과일**, 색은 **이월 횟수**다. 둘이 다른 것을 재기 때문에 일부러 나눴다.

| carriedCount | 색 | 뜻 |
|---|---|---|
| 0 | 배지 없음 | 오늘 만든 것 |
| 1–2 | `text-tertiary` | 조용히 표시만 |
| 3–6 | `warning` | 밀리고 있다 |
| 7+ | `danger` + 툴팁 | "이거 정말 할 건가요?" |

7일째 힌트를 **항목 옆 문구가 아니라 툴팁**에 두는 이유: 좀비가 5개면 같은 문장이
5번 반복되고, 한 줄짜리 항목 옆에 문장이 붙으면 텍스트가 잘린다. 색이 이미
신호이므로 문구는 확인용으로 충분하다.

### 4-d.3 상태별 표현

| 상황 | 표현 |
|---|---|
| 오늘, 항목 없음 | `할 일을 추가하세요` |
| 과거, 항목 없음 | `이 날 완료한 항목이 없습니다` — 이월이 이동이라 과거엔 완료본만 남는다 |
| 미래, 항목 없음 | `이 날 할 일이 없습니다` |
| 이월 발생 | 별도 알림 없음. 항목에 붙는 `↻ N일째` 배지가 곧 신호다 |
| 저장 실패 | 목록 위에 danger 줄. 항목은 바뀌지 않은 채로 남는다 |

### 4-d.4 편집

- 체크·삭제는 **즉시** 저장된다
- 텍스트는 클릭하면 입력으로 바뀌고 **Enter/blur에서만** 저장한다 — 글자마다 디스크를 때리지 않는다
- Escape는 편집을 취소한다
- 빈 텍스트로는 저장되지 않는다. 지우려면 `×`를 쓴다 — 삭제는 명시적이어야 한다

## 5. 에러 표현 — 위젯 vs 전역

### 5.1 경계

| | 위젯 인라인 | 전역 배너 |
|---|---|---|
| 대상 | 그 위젯만의 문제 | 서비스 전체 문제 |
| 예 | 400 JQL, 403 권한 | **401 토큰 만료** |
| 위치 | 위젯 본문/하단 | 앱 최상단 |
| 개수 | 위젯마다 | 서비스당 **하나** |

**판단 기준 한 줄:** *"이 에러가 같은 서비스의 다른 위젯에도 똑같이 날 것인가?"*
그렇다면 전역. 아니면 인라인.

### 5.2 전역 배너

401은 그 서비스의 위젯 전부가 동시에 깨진다. 위젯 4개에 같은 에러 4번은 소음이다.

```
┌──────────────────────────────────────────────────────────┐
│ ⚠  Jira 인증 실패 — API 토큰이 만료되었습니다   [설정 열기]  ✕ │  36px
└──────────────────────────────────────────────────────────┘
   danger-muted 배경 · 하단 border 1px danger
```

| 항목 | 사양 |
|---|---|
| 위치 | 보드 위, 앱 최상단. 고정 (스크롤 안 됨) |
| 높이 | 36px |
| 배경 | `danger-muted` |
| 하단선 | `danger` 1px |
| 글자 | `text-sm` / `text-primary` |
| 등장 | 위에서 슬라이드, `duration-slow` |

**배너가 떠 있는 동안 해당 서비스 위젯들은:**
- `stale` 상태로 (캐시 데이터 유지, 감쇠)
- 개별 에러 표시 **없음**
- 헤더 시계 아이콘 없음 (배너가 이미 말하고 있다)
- 새로고침 버튼 비활성

**해제:** 재인증 성공 시 배너가 사라지고 모든 위젯이 즉시 재조회.

**동시에 두 서비스가 실패하면** 배너 2줄. 최대 2개이므로 스택 관리가 불필요하다.

### 5.3 토스트를 쓰지 않는 이유

`sonner`를 안 넣기로 했다(DECISIONS 18장). 이유가 여기서 구체화된다:

- **실패**는 위젯이나 배너에 **머물러야** 한다. 토스트는 3초 뒤 사라져서
  자리를 비운 사이에 놓친다.
- **성공**은 화면 변화 자체가 알린다. 티켓이 생성되면 목록에 나타난다.
  "생성되었습니다" 토스트는 같은 말을 두 번 하는 것이다.

**예외 하나 — 되돌리기.** 위젯 삭제 후 5초간 배너 자리에 표시.
이건 알림이 아니라 **시간 제한이 있는 행동 제안**이라 다르다.

## 6. 밀도 — 폭에 따른 변화

12열 그리드. 위젯 폭에 따라 **레이아웃이 구조적으로 바뀐다.**
글자 크기는 어느 폭에서도 바뀌지 않는다.

### 6.1 3열 (약 240px) — 최소

```
┌────────────────────────┐
│ 내 티켓           ⟳   │
├────────────────────────┤
│ ABC-412  로그인 토큰... ● │
│ ABC-408  대시보드 초...  ● │
│ XYZ-77   강의 목록 페... ● │
├────────────────────────┤
│ 3분 전            30건 │
└────────────────────────┘
```

- 한 줄 행, 28px
- 상태 = 6px 점
- 담당자 = 아바타만
- 시각 표시 없음 (푸터에만)
- **요약문 약 7~8자**

**3열이 하한선이다.** 그리드 `minW: 3`으로 강제한다. 2열에서는 요약이 3자가 되어
목록의 의미가 없다.

### 6.2 6열 (약 500px) — 표준

```
┌──────────────────────────────────────────────┐
│ 내 티켓                          ⟳  ⚙  ✕    │
├──────────────────────────────────────────────┤
│ ABC-412  로그인 시 토큰 갱신 실패              │
│          [진행중]  현우  ·  2시간 전           │
├──────────────────────────────────────────────┤
│ ABC-408  대시보드 초기 로딩 최적화             │
│          [할일]    현우  ·  어제              │
├──────────────────────────────────────────────┤
│ 3분 전 갱신                            30건   │
└──────────────────────────────────────────────┘
```

- 두 줄 행, 44px
- 텍스트 배지 + 담당자 이름 + 상대 시각
- **요약문 약 25~30자** — 대부분의 제목이 안 잘린다

**이것이 기본값이다.** 새 Jira 위젯은 `w: 6, h: 8`로 생성한다.

### 6.3 12열 (전체 폭) — 확장

```
┌────────────────────────────────────────────────────────────────────────┐
│ 내 티켓                                                  ⟳  ⚙  ✕      │
├────────────────────────────────────────────────────────────────────────┤
│ ABC-412  로그인 시 토큰 갱신 실패            [진행중]  현우  버그  2시간 전│
│ ABC-408  대시보드 초기 로딩 최적화 작업       [할일]   현우  개선  어제   │
├────────────────────────────────────────────────────────────────────────┤
│ 3분 전 갱신                                                      30건   │
└────────────────────────────────────────────────────────────────────────┘
```

- **다시 한 줄로 돌아간다.** 28px
- 이슈 타입 아이콘 추가
- 라벨 1개까지 표시
- 요약문 폭 상한 **480px** — 그 이상은 남는 공간을 우측 메타에 준다

**왜 12열에서 한 줄로 돌아가나:** 폭이 넓으면 두 줄 배치는 우측이 텅 빈다.
한 줄에 다 들어가면 **화면당 항목 수가 2배**가 된다. 대시보드에서는
"한눈에 몇 개가 보이나"가 값어치다.

**왜 요약문에 상한을 두나:** 480px 넘게 늘리면 눈이 좌우로 크게 움직여야 한다.
한글 기준 30~35자가 한 번에 읽히는 한계다.

### 6.4 정리

| 폭 | 행 | 높이 | 상태 | 담당자 | 시각 | 요약 |
|---|---|---|---|---|---|---|
| 3열 | 1줄 | 28px | 점 | 아바타 | — | ~8자 |
| 4~5열 | 1줄 | 28px | 배지 | 아바타 | — | ~15자 |
| 6~8열 | 2줄 | 44px | 배지 | +이름 | 있음 | ~30자 |
| 9열+ | 1줄 | 28px | 배지 | +이름 | 있음 | ~35자 (상한) |

**높이 방향:** 행 높이가 고정이므로 위젯 높이 = 보이는 항목 수다.
`h: 8`(약 320px) → 헤더32 + 푸터24 = 264px 본문 → 한 줄 행 9개 / 두 줄 행 6개.

## 7. 한글 타이포그래피

### 7.1 서체 스택

```
Pretendard Variable → Pretendard → -apple-system → Apple SD Gothic Neo
→ Noto Sans KR → system-ui
```

**Pretendard가 1순위인 이유:**

한글과 라틴을 **한 벌로** 처리한다. 이게 핵심이다.
`-apple-system`을 먼저 두면 이런 일이 생긴다:

```
ABC-412 로그인 시 토큰 갱신 실패
└──┬──┘ └──────────┬─────────┘
 SF Pro      Apple SD Gothic Neo
```

한 줄 안에서 두 서체가 섞인다. 획 굵기와 x-height가 달라 라틴이 뜬다.
목록에 티켓 키가 매 행 나오는 이 앱에서는 매 행마다 이 문제가 생긴다.

**번들하지 않는다.** 웹폰트를 넣으면 첫 렌더가 늦어지거나 FOUT이 생긴다.
"0ms 표시"가 목표인 앱에서 폰트 로딩을 기다릴 수 없다. 설치돼 있으면 쓰고,
없으면 Apple SD Gothic Neo로 떨어진다. 후자도 macOS에서 충분히 좋다.

### 7.2 왜 한글은 행간이 달라야 하나

라틴과 한글은 글자 구조가 다르다.

| | 라틴 | 한글 |
|---|---|---|
| 글자틀 | 폭이 제각각 (i vs W) | **정사각형 고정** |
| 세로 구성 | x-height + 어센더/디센더 | 초성+중성+**종성** |
| 단어 경계 | 대소문자 + 공백 | 공백만 |

**세 가지 결과:**

1. **같은 px에서 한글이 더 크고 빽빽해 보인다.**
   라틴 소문자는 x-height가 폰트 크기의 약 70%지만, 한글은 글자틀을 거의 꽉 채운다.

2. **받침이 세로 공간을 먹는다.**
   "가"와 "갏"의 높이가 다르다. 받침 있는 글자가 많은 줄은 아래로 늘어나
   다음 줄과 붙어 보인다.

3. **단어 경계가 약하다.**
   대소문자 구분이 없어 덩어리로 보인다. 줄이 붙으면 어디가 줄 끝인지 놓친다.

**→ 라틴 기준 행간(1.4~1.5)을 한글에 그대로 쓰면 답답하다.**

### 7.3 행간 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `leading-none` | 1 | 아이콘 정렬, 단일 배지 |
| `leading-tight-latin` | 1.25 | 티켓 키, 숫자 |
| `leading-tight-ko` | **1.45** | 한글 한 줄 (목록 요약) |
| `leading-normal-ko` | **1.6** | 한글 여러 줄 (본문) — 기본값 |
| `leading-relaxed-ko` | **1.75** | 긴 한글 (ADF 본문, 코멘트) |

`tight-ko`(1.45) > `tight-latin`(1.25)인 것이 요점이다.
한글은 "좁게" 조차 라틴의 "보통"보다 넓다.

**ADF 본문에 1.75를 쓰는 이유:** 상세 모달의 description은 유일하게
"읽는" 텍스트다. 나머지는 전부 "스캔"한다. 읽는 텍스트는 넉넉해야 한다.

### 7.4 자간

```
--tracking-tight: -0.01em
```

**한글은 자간을 좁히면 금방 뭉갠다.** 라틴에서 흔한 -0.02~-0.03em을 한글에
적용하면 받침과 다음 글자가 붙는다. **-0.01em이 한계**다.

`tracking-wide`(0.02em)는 **대문자 라틴 배지 전용**이다. 한글에 쓰지 않는다.

### 7.5 줄바꿈

```css
word-break: keep-all;
overflow-wrap: break-word;
```

`keep-all`이 필수다. 없으면 브라우저가 한글을 글자 단위로 자른다:

```
로그인 시 토큰 갱신 실   ← 나쁨
패
```

```
로그인 시 토큰           ← 좋음
갱신 실패
```

`overflow-wrap: break-word`를 함께 두는 이유: `keep-all`만 두면 긴 URL이나
붙여쓴 영문이 컨테이너를 뚫는다.

### 7.6 숫자

```css
font-variant-numeric: tabular-nums;
```

전역 적용. 목록에서 "3분 전"·"12분 전"의 숫자 폭이 다르면 세로 정렬이 흔들린다.
등폭 숫자는 갱신될 때 레이아웃이 움직이지 않게 한다.

### 7.7 안티에일리어싱

**`-webkit-font-smoothing: antialiased`를 쓰지 않는다.**

라틴 다크 테마에서는 흔한 처방이지만, 한글에서는 획이 끊겨 보인다.
한글은 획이 많고 서로 가까워서 얇아지면 자소가 붙거나 사라진다.
macOS 기본 렌더링(subpixel)이 한글에 더 낫다.

### 7.8 크기 선택 기준

| 상황 | 토큰 | 값 |
|---|---|---|
| 스캔하는 목록 | `text-sm` | 13px |
| 읽는 본문 | `text-base` | 14px |
| 메타 정보 | `text-xs` | 12px |
| 배지 | `text-2xs` | 11px |

**11px이 하한이다.** 한글은 10px 아래에서 받침이 뭉개져 판독이 안 된다.
라틴은 10px에서도 읽히지만 한글은 아니다.

## 8. 접근성 기준선

혼자 쓰는 앱이라고 접근성을 빼지 않는다. 이유는 접근성이 아니라 **품질**이다 —
명암비가 낮은 화면은 하루 종일 보면 눈이 아프다.

| 항목 | 기준 | 확인 |
|---|---|---|
| 본문 명암비 | 4.5:1 | `theme.css` 상단 실측표. 전 조합 통과 |
| 비텍스트 명암비 | 3:1 | `border-strong`, `focus-ring` 통과 |
| 포커스 표시 | 모든 대화형 요소 | `:focus-visible` 전역 |
| 키보드 조작 | 목록 행 포함 | 행은 `tabindex="0"` + Enter |
| 색 단독 의존 금지 | — | 아래 참조 |
| 모션 최소화 | 존중 | `prefers-reduced-motion` |

**색에만 의존하지 않는 세 지점:**

1. **상태** — 색 + 텍스트 라벨. 3열의 점 표현은 `title` 속성 필수
2. **우선순위** — 색 + 위치(좌측 선). 상세 모달에서는 이름 표기
3. **stale** — 색 + 시계 아이콘 + "N분 전 데이터" 문구

**`text-quaternary`는 본문에 쓰지 않는다.** 4.5:1을 못 넘는다.
구분 기호(·, /), 비활성 아이콘, 이미 다른 곳에 표기된 정보의 중복 표시만.

## 9. 하지 않기로 한 것

| 항목 | 이유 |
|---|---|
| 위젯 그림자 | 경계선 1px로 충분. 겹치면 유령 카드 |
| 중첩 카드 | 위젯 안의 카드는 항상 잘못된 설계 |
| 스켈레톤 펄스 | 위젯 6개가 동시에 깜빡이면 요동친다 |
| 등장 애니메이션 | 0.3초 페이드인 = 0.3초 느린 것 |
| 위젯별 브랜드 색 | 색은 상태 전용 (원칙 1) |
| 토스트 | 실패는 머물러야, 성공은 화면 변화로 |
| 빈 상태 이모지 | 하루 수십 번 보면 성가시다 |
| 유동 타이포(clamp) | 같은 정보가 위젯마다 달라 보인다 |
| 커스텀 스크롤바 동작 | 색만 맞추고 동작·크기는 네이티브 |
| 다크/라이트 토글 애니메이션 | 테마 전환은 즉시. 중간 상태가 더럽다 |

## 10. 구현 점검표

새 위젯을 만들 때 확인:

- [ ] `WidgetShell`을 쓴다. 헤더·푸터를 직접 그리지 않는다
- [ ] 7개 상태를 전부 처리한다 (`empty` 빠뜨리기 쉬움)
- [ ] 데이터가 있는 상태에서 갱신 시 **본문을 비우지 않는다**
- [ ] 3열 폭에서 확인했다
- [ ] 원시 색(`--palette-*`)을 직접 참조하지 않는다
- [ ] 라이트 테마에서 확인했다 (`data-theme="light"`)
- [ ] 목록 행이 키보드로 도달·실행된다
- [ ] 긴 한글 제목에서 `keep-all`이 동작한다
- [ ] 담당자 이미지 로딩 실패 시 깨진 아이콘이 안 나온다
