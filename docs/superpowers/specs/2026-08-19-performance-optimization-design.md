# 렌더링 및 초기 로딩 성능 최적화 설계

## 목표

사용자에게 보이는 동작과 저장 형식을 바꾸지 않고 두 병목을 줄인다.

1. Todo 작업 한 건이 끝날 때 Rust가 돌려주는 전체 배열 때문에 변경되지 않은 행까지 다시 렌더되는 문제
2. 닫힌 설정 UI가 시작 번들에 포함되어 앱 시작 시 함께 파싱되는 문제

## 현재 근거

- `bun run build`의 초기 JavaScript 청크는 minified 500.17KB, gzip 137.07KB이며 Vite의 500KB 경고를 발생시킨다.
- `TodoRowBound`는 id별 selector로 변경된 행만 구독하도록 설계되어 있지만, 모든 성공 응답이 `items: r.data`로 전체 객체를 교체하므로 실제로는 모든 selector 결과가 달라진다.
- `App`은 닫힌 `SettingsModal`을 정적으로 import하고, 각 위젯 등록 파일은 설정 폼을 정적으로 import한다. 이 코드는 첫 보드 표시에는 필요하지 않다.

## 설계

### Todo 객체 정체성 보존

`src/store/todos.ts`에 현재 배열과 서버 응답 배열을 병합하는 순수 함수를 둔다. id가 같고 사용자 데이터 필드가 모두 같은 항목은 기존 객체를 재사용하고, 변경·추가된 항목만 새 객체를 사용한다. 배열 순서는 항상 서버 응답을 따른다. 모든 Todo 성공 경로는 이 함수를 통해 상태를 갱신한다.

### 닫힌 설정 UI 코드 분할

`SettingsModal`은 타입만 정적으로 가져오고 컴포넌트는 `React.lazy`와 동적 import로 불러온다. 닫혀 있을 때는 lazy 컴포넌트를 마운트하지 않아 import 자체가 시작되지 않도록 한다.

각 위젯 등록 파일도 `ConfigForm`을 lazy 컴포넌트로 등록한다. `WidgetConfigModal`은 기존 모달 골격과 접근성 동작을 유지하고 폼 청크가 로드되는 짧은 동안 기존 로딩 문구를 표시한다. 위젯 본문은 첫 화면에 필요하므로 정적 import를 유지한다.

## 오류 및 UX 경계

- 동적 import를 위한 별도 재시도 UI나 새로운 전역 오류 상태는 추가하지 않는다. Tauri가 로컬 자산을 제공하므로 일반 네트워크 지연 경로가 아니다.
- Suspense fallback은 레이아웃을 흔들거나 새 애니메이션을 만들지 않는다.
- 설정창의 열림/닫힘, 초기 탭, 저장 콜백과 위젯 설정 유효성 계약은 유지한다.
- Todo 데이터의 순서, 필드, 파일 저장 형식과 IPC 계약은 바꾸지 않는다.

## 검증

사용자 요청에 따라 새 테스트 작성과 전체 테스트 실행은 생략한다. 대신 `bun run typecheck`, `bun run lint`, `bun run build`를 실행하고 초기 청크의 minified/gzip 크기와 Vite 500KB 경고 유무를 기준값과 비교한다. 변경 diff를 직접 검토해 정적 import가 남아 있거나 불필요한 동작 변경이 없는지 확인한다.
